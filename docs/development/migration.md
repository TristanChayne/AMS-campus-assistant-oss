# 分批迁移计划

2026-10-16 用户授权开始仓库整理。现阶段先建立依赖地图、无凭证检查和协作入口；业务工程仍使用现行路径。下表中的目标路径是迁移设计，不代表已经实现，也不代表批准重写平台或拆服务。

## 顺序与验收

| 批次 | 范围 | 完成标准 |
|---|---|---|
| A 基础 | 开发指南、源码地图、README 历史归档、tools/repo、PR/Issue/CI、仓库标签 | 干净检出执行现有离线回归；缺失输入明示；业务源/资源不变 |
| B 可重建输入 | 小程序四份依赖安全提取、开发工具版本和非敏感依赖清单；Android 独立 Debug 路径 | 不使用私有缓存/正式签名完成约定生成或开发构建；实际结果核对后再称完成 |
| C 共享输入 | 先迁现有手写共享页面与适配源码，消除 Android 作为 iOS 输入中转 | 两端生成链明确；逐文件差异可解释；关键回归及所需原生构建通过 |
| D 工程路径 | 按活动分支和真实依赖逐个迁移工程/工具，统一服务作为一个部署边界 | 引用/测试/部署打包输入/备份导出清单同步；旧客户端协议不变；不实际部署验收目录 |
| E 功能模块 | 只拆确有多人冲突的业务大文件；完善构建/浏览器 CI | 每次只处理一个边界；平台可保留原生习惯，不强求同构 |

每批完成都由协调方更新同一 TASKS/项目进度，再独立提交与注释标签；详细技术笔记可本地保留。这份文件只维护迁移路线，不另建进度日志。开始下一批先核对活动分支、归属和工具环境，不能跨过输入缺口机械搬目录。

## 目标映射

| 当前入口 | 候选目标 | 约束 |
|---|---|---|
| outputs/ams-android | apps/android | 保留 Java/Android 工程内部布局 |
| outputs/ams-ios | apps/ios | 保留原生工程及 Widget；核对生成器、Mac 同步和签名 |
| outputs/ams-miniprogram | apps/miniprogram | 先解决生成器输入 |
| outputs/ams-admin | apps/admin | 保持真实会话与显式 preview 隔离 |
| outputs/ams-notify + 复用激活源码 | services/ams + 明确的模块/兼容入口 | 先画清现有依赖；不拆数据库/服务，不删除旧入口 |
| work 中实际共享网页输入及手写预约 assets | shared/web | 先确认每个文件是手写还是生成；不创建泛化 utils 杂物箱 |
| work 构建/生成/检查/备份脚本 | tools 中对应职责目录 | 逐步移动；当前 tools/repo 已可用，历史脚本先标注用途 |
| 历史包、截图、捕获、缓存 | 本地产物/私有存储 | 不批量删除，不为目录整齐复制入 Git |
| 宣传制作源码 | 是否独立 creative 或单独仓库待协作需求决定 | 素材授权与仓库源码权限分开 |

本阶段不创建 apps/services/shared 的空壳，不替换现有工作区。目录迁移使用 git 跟踪的逐文件变更；源路径移动与业务行为重写分开审阅。

## 每批核对

1. 已认领范围与活动分支不冲突，main 同步且未知修改已查清。
2. 新路径在 Git 允许列表中，旧本地材料保持原位；不将放宽忽略规则作为省事办法。
3. 同步脚本中的 cwd、相对根路径、测试入口、文档链接和部署组装清单。个人工具和详细接手资料不入Git；其本地导出不等于仓库交付。
4. 在独立干净检出运行相关生成/检查，保留预期差异与缺失项。平台编译和设备验收各自报告。
5. 需要切换生产入口或迁移数据时单独形成方案与备份，目录整理本身不自动执行它们。

## 自动化后续

当前云工作流只提供 smoke/service 基线，不包含完整构建或发布。云端实际运行后再设置必过检查；将来的新签名、部署和商店流程使用独立受控环境。是否公开仓库、扩大成员权限或采购服务需要对应明确任务。
