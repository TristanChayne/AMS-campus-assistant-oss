## 0.2 扫码调整

0.3 更新：采用接近 1280×720 的预览尺寸、连续取帧、连续视频对焦及点击画面对焦，支持全画面/中心区域和反色二维码识别。顶部显示已识别的帧数，便于区分未收到画面与解码失败。13 项合成图像检查覆盖不同尺寸、旋转、反色及空白画面，编译和签名校验通过；真实手机的清晰度、取帧与课堂二维码仍需验证。

2026-10-05 检查学校公开手机网页脚本，发现首页 `onORCode` 只在微信环境调用微信扫码，其他环境仅显示浏览器提示。参考地址：<https://ams.xjtlu.edu.cn/studenth5/static/js/chunk-52247a66.64ed0653.js>。

点击学校主页原有 **Scan Sign-in QR Code** 按钮，即可打开 App 相机。顶部独立入口已移除。App 在本地通过 ZXing 3.5.3 识别二维码，按学校当前扫码逻辑取 `split('=')[1]`，直接调用主页组件原有 `onSubmit`；学校继续负责有效性、时限和最终结果。识别后不再出现确认框；识别前按返回键可取消。若学校组件或二维码格式变化，需要更新适配。此版本不冒充微信浏览器，也不修改学校验证逻辑。

依赖 JAR 位于 `E:\DevTools\AndroidTools\Libraries\zxing-core-3.5.3.jar`，来自 Maven Central，已比对官方 SHA-1。ZXing 使用 Apache 2.0 许可证：<https://github.com/zxing/zxing/blob/zxing-3.5.3/LICENSE>。

账号密码只在学校页面输入；源码不含账号密码。WebView 在应用私有存储中保留学校会话 Cookie。外部浏览器的登录状态与应用相互独立，浏览器登录不会自动登录本应用。卸载或清除应用数据可清除本地会话。

## 构建

最新包为 `ams-prototype-0.9.1-debug.apk`，可直接复制到安卓手机覆盖安装。Android 8.0 及以上可安装；这是本地调试版本，与第一版使用同一签名。

0.9 更新：移除“原版”按钮。首页、记录列表、请假列表、code 输入和签到结果统一由持续保留的界面层展示，学校组件继续提供数据和校验。结果根据学校 signCodeSuccess/signCodeFail 路由展示，不通过动画判断成功。Code 使用学校 signCode 组件原 onSubmit，沿用 type=2；二维码沿用 type=1。课程记录和请假列表点击继续调用学校 goDetail，复杂的记录详情/请假申请/课程选择页面仍保留学校功能控件，由统一样式接管外观，并未重写成独立表单；文件上传和真实申请提交尚未验证。

相机入口改为只提供 open 操作的 JavaScript 原生桥，进入扫码不需网页导航中转；主框架地址必须是 AMS HTTPS 手机页面才允许启动。原桥 fallback 导航仍兼容。Camera.open 移到工作线程，在界面线程配置预览，启动/返回去掉 Activity 转场动画。后台打开后若界面已关闭则释放相机。手机实际启动时长及生命周期仍需验收。

模拟学校组件的路由检查覆盖首页→记录→请假→code→成功结果→首页，验证界面层复用、数据映射、Code 原方法调用及申请表样式路径，未执行网络签到或请假。APK 编译/签名检查通过。手机需依次验收扫码启动、扫描取消返回、真实签到结果、记录与详情、code 提交、请假查看和表单控件；不能据自动检查认定学校业务验收通过。

0.8.2 更新：按钮取消浏览器默认触屏高亮，增加裁剪在按钮边界内的涟漪与轻微按压缩放；键盘焦点改为向内绘制，避免越界。尊重系统减少动画设置。按钮启用 touch-action: manipulation，降低双击手势引起的等待；原页面跳转改为监听学校路由完成事件，及时移除新首页覆盖层，而不只依赖 500ms 轮询。路由回调检查、原有数据检查、编译和签名检查通过，手机动画体验和真实响应时间尚未实测。动画并不代表签到成功，仍以学校返回的结果为准。

0.8.1 修复：用户反馈 0.8 仍显示原版。组件发现不再依赖 `.index` 根节点和直接子组件，改为从页面挂载的 Vue 实例遍历父/子组件，通过已使用的首页方法和 `/home` 路由识别首页，再递归发现课表数据。App 恢复前台时再次执行幂等初始化。新增嵌套首页/课表组件检查通过，构建与签名验证通过；尚未在用户实际手机会话确认该问题已修复。

0.8 更新：登录后首页使用新的三天课表视图。读取学校页面已经返回的 `scheduleList` / `timetableVoList`，使用 `moduleTime`、`moduleTitle`、`room`、`moduleCode`、`moduleTypeGroup`，没有额外请求接口，也没有示例课程。只在原首页显示隔离的界面层，其他路由仍使用学校页面；按钮继续使用原扫码、code 签到、记录和请假流程。学校原页面和组件保留，用于现有签到处理。点击“原版”可在当前页面会话中回到学校首页；重新启动/加载文档可再次显示新版。是否显示请假入口遵循学校原导航。

课程根据手机当前时间显示状态，每分钟刷新；已结束课程折叠。未提供的时间或教室标记为待确认，未返回的日期标记为尚未读取。日期顺序沿用学校返回数据，前三项对应今天、明天、后天。学校提供新的数据或格式后可能需更新适配。没有时间模拟按钮，不改签到规则。代码映射、模拟组件路由、日期缺失、文本转义及界面状态检查和 APK 构建/签名检查通过；真实学校会话、路由与手机展示仍需用户验收。

0.7 更新：主界面只显示学校网页，移除域名状态文字、首页/刷新/浏览器按钮及加载进度条；网络错误出现时提供重试提示。保留系统状态栏和导航区避让。相机页面移除放大/缩小按钮与调试帧数，改为双指缩放、单指点击对焦；双指手势不会触发点击对焦，缩放按相机支持范围限制。编译、签名和网页入口检查通过，手势及实际页面布局需手机验收。

0.6 更新：在 AMS HTTPS 手机页面安装一次捕获阶段点击处理器，匹配学校原有 `.buttonbox.left-cancel` 和二维码图标，拦截原提示并使用本地导航打开 App 相机。事件代理适用于登录后动态渲染和返回主页；无需读取账号或新增 JavaScript 原生接口。仅主框架、当前 AMS 手机页面允许打开扫码，相机结果返回和自动提交保持 0.5 逻辑。脚本路由检查及构建、签名检查通过，手机按钮点击仍需实测。

0.5 更新：按用户要求去掉提交确认框；在常规解码失败后，尝试中心区域的横向比例补偿，覆盖屏幕将二维码拉宽/拉高的情况。7 项合成拉伸测试（0.5 至 2 倍）及原有 13 项解码检查通过。桌面测试不代表手机解码延迟或课堂签到成功；复杂透视、模糊或缺失像素仍可能无法识别。补偿时需将完整二维码居中。

0.4 更新：用户截图显示帧计数正常，离线使用现有解码器也无法识别该截图。修正预览长宽比例以避免拉伸，避让系统状态栏，优先选择接近 1920×1080 的预览，并增加放大/缩小按钮。预览比例修正不直接修改原始解码帧；提高分辨率和放大用于改善密集二维码的采样。需手机重新验证，不能据此保证真实签到成功。

## 手机验收

1. 安装 APK，在学校页面手动登录，确认能进入 AMS；若白屏，记录停留的域名，点击 AMS 首页重试。
2. 检查课表的日期、上课时间、教室与外部浏览器一致。
3. 在允许签到的真实课堂，点击学校主页原有“Scan Sign-in QR Code”，允许相机，将完整二维码居中。识别后自动提交，以学校页面实际返回的签到记录为准。可以提前打开相机等待二维码出现，以减少 10 秒窗口内的操作。
4. 测试拒绝相机权限，再次打开扫码页面授权；code 签到应仍能使用。
5. 在真实允许签到的课堂输入有效 code，检查学校返回结果。不要用刷新按钮重复提交签到。
6. 测试返回键、切换应用、断网提示以及重启后的登录状态。

当前未直接调用学校后台签到接口；请假表单通过学校现有附件和申请接口提交。未在手机上验证附件上传、定位或特殊扫码协议。扫码成功与签到成功不同：以学校最终页面和签到记录为准。

0.9.1 更新：签到课程明细由应用接管，使用紧凑卡片、中文状态和教学组/日期/出勤状态筛选，保留学校分页。请假无记录时采用图标与小字号空状态。扫码页隐藏系统状态栏，移除顶部说明栏，加入取景框与循环扫描线，保留双指缩放、点击对焦和识别后自动提交。动画仅表示识别中。

登录后预先读取当前学期签到记录及开放的请假列表（仅只读 GET，沿用当前学校会话），内存缓存先显示，后台每分钟检查更新，不在切换时清空；后台失败保留已有内容。账户变化清除缓存。首次登录仍需等待网络首次读取，课程明细按筛选条件加载。签到成功后触发后台刷新。

0.9.1 已通过 Java/DEX/APK 构建、签名及对齐校验，模拟页面适配器的预加载、缓存保留、筛选、分页检查，以及 390px 宽浏览器静态布局检查。未连接手机，扫描动画和真实学校接口的后台预加载仍需手机验收。
